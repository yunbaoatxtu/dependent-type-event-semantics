# A Dependent-Type Replacement for Event Semantics: Variable Polyadicity, Argument Omission, Thematic Roles, Event Counting, and Causal Resultatives

_Manuscript draft prepared for conceptual and formal development_

## Abstract

Event semantics has provided a powerful architecture for the analysis of natural-language predication: it explains variable polyadicity, supports argument-omission inferences, hosts thematic-role modifiers, and gives uniform treatments of temporal modification, event counting, causation, resultatives, and discourse anaphora. However, its uniform hidden-event variable also conflates several distinct semantic tasks. This article proposes a modular dependent-type alternative in which the functions performed by event variables are decomposed into typed role records, dependent families indexed by natural numbers, sigma types for implicit arguments, interval-indexed temporal operators, state-transition types for causal resultatives, and episodic witnesses introduced only when counting or discourse reference requires them. The resulting framework preserves the empirical coverage of event semantics while avoiding the ontological and compositional overgeneration associated with assigning an event argument to every predicate. We define a formal translation from neo-Davidsonian conjunctions into dependent-type terms, give rules for argument deletion, thematic-role saturation, temporal and aspectual modification, event counting, causation, and result states, and show how the system can be implemented as an automatic translator. The implementation emits both a readable formula and a structured abstract syntax tree with a shallow type-checking layer for sigma witnesses, repetition, temporal operators, and causal transitions. The proposal yields a typed, modular, and computationally tractable semantics in which events are no longer the default glue of predication but one derived representational option among several.

**Keywords:** dependent type theory; event semantics; neo-Davidsonian semantics; argument omission; thematic roles; causation; resultatives; event counting; natural language semantics

## 1. Introduction

Event semantics has become one of the central tools of formal semantics because it gives a simple answer to several otherwise unrelated problems. A sentence such as John buttered the toast slowly in the bathroom at noon can be analyzed by positing an event variable e and conjoining predicates over it: butter(e), Agent(e, John), Theme(e, toast), slowly(e), in(e, bathroom), and at(e, noon). This analysis explains why modifiers can accumulate without changing the lexical arity of the verb. It also gives a natural host for thematic roles, temporal localization, manner modification, instruments, locations, and subsequent event anaphora.

The elegance of this architecture is also its weakness. The event variable is asked to do too many jobs. It counts modifier positions, represents implicit arguments, supports role labeling, anchors time, provides a unit for counting, mediates causation, licenses result states, and sometimes serves as a discourse referent. These functions are not semantically identical. A manner adverb, an implicit object of eat, a result state in break, a repeated occurrence in knock twice, and an anaphoric expression such as that happened again do not require the same kind of object. Treating them all as consequences of one hidden event argument risks turning a useful notation into an overly general ontology.

This article develops a replacement strategy rather than a rejection of the phenomena. The central hypothesis is that the empirical advantages of event semantics can be preserved if the hidden event variable is decomposed into typed components. Variable polyadicity is handled by a dependent family indexed by natural numbers. Thematic-role structure is handled by dependent role records. Argument omission is handled by sigma types and option types. Temporal and aspectual modification is handled by interval-indexed operators. Causal resultatives are handled by state-transition types. Event counting is handled by finite vectors of episode witnesses, introduced only in environments where counting or discourse reference demands them. The result is a modular semantics that keeps the expressive gains of event semantics while giving each phenomenon its own type-theoretic mechanism.

## 2. Background and Motivation

Davidsonian and neo-Davidsonian event semantics introduced an event variable as an additional argument of action predicates. The neo-Davidsonian development separates the core event predicate from thematic roles, allowing the semantic contribution of modifiers and arguments to be expressed as independent conjuncts. This architecture is attractive because it converts apparently variable-arity predicates into a uniform conjunctive form.

The type-theoretic critique begins from the observation that variable polyadicity need not be represented by an event ontology. Luo and Shi argue that the ability of a verb to combine with an arbitrary number of adverbial modifiers can be modeled in an extension of Church's type theory with dependent products and the natural-number type. If ADV is the type of predicate modifiers, a transitive verb can be assigned the dependent type Pi n : N. TV-ADV(n), where TV-ADV(0) = e -> e -> t, TV-ADV(1) = ADV -> e -> e -> t, and TV-ADV(n + 1) adds one more modifier argument. A verb such as butter can therefore take zero, one, two, or more modifiers without positing an event variable.

Yet variable polyadicity is only one reason event semantics has been successful. A credible replacement must also address argument omission, role-based modification, temporal reference, aspect, event counting, causal structure, result states, and event anaphora. The contribution of the present article is to extend the dependent-type strategy from variable polyadicity to this wider empirical domain.

## 3. The Event-Variable Decomposition Thesis

The proposed framework is based on the Event-Variable Decomposition Thesis: the hidden event variable in neo-Davidsonian semantics is not a semantically atomic object but a bundle of representational functions. A replacement system should therefore map each function to a typed construction with a narrower domain of application.

The decomposition is summarized as follows. Modifier accumulation is handled by natural-number-indexed predicate families. Role assignment is handled by dependent records whose fields are typed by selectional and thematic constraints. Argument omission is handled by existential dependent pairs or option types. Temporal location is handled by interval and time-point operators over propositions or processes. Aspect is handled by process and culmination types. Causation and resultatives are handled by state-transition types. Counting is handled by finite vectors or lists of episode witnesses. Discourse anaphora is handled by optional introduction of a referential situation or episode token, not by a universal event parameter.

## 4. Formal Architecture

We assume base types Entity, Truth, Time, Interval, State, and Nat. We also assume a type of predicate modifiers ADV = (Entity -> Truth) -> (Entity -> Truth), generalized where necessary to role-record predicates. For an intransitive predicate family we define IV-ADV(0) = Entity -> Truth and IV-ADV(n + 1) = ADV -> IV-ADV(n). For a transitive predicate family, TV-ADV(0) = Entity -> Entity -> Truth and TV-ADV(n + 1) = ADV -> TV-ADV(n). More generally, Vk-ADV(n) = ADV^n -> Entity^k -> Truth.

A lexical verb is assigned a dependent type of the form V : Pi n : Nat. Vk-ADV(n). This captures variable polyadicity. For example, butter : Pi n : Nat. TV-ADV(n). The term butter(2)(slowly, in(bathroom), John, toast) denotes the proposition that John buttered the toast slowly in the bathroom, with the two modifiers counted by the index 2.

Thematic-role information is not lost. Instead of representing roles as conjuncts Agent(e, x) and Theme(e, y), the system constructs a role record. A simplified transitive frame has the form { agent : AgentiveEntity; theme : Entity; instrument? : Tool; location? : Place; manner : Vec ADV n; time? : Interval }. The role record can be made dependent: the admissible type of theme may depend on the lexical verb, and the admissible type of instrument may depend on both the verb and the theme.

Argument omission is modeled by dependent existential types. For verbs whose lexical semantics licenses implicit objects, we assign a rule such as eat : Human -> Option Food -> Truth, together with an inference from eat(john, none) to Sigma x : Food. eat(john, some x). The inference is lexical and constructional rather than a consequence of an event variable. In contrast, a verb such as arrive does not introduce a missing theme, and a verb such as butter normally requires an overt or contextually recoverable theme.

## 5. Translation from Neo-Davidsonian Formulas

The input language consists of formulas of the form exists e. Verb(e) and R1(e, x1) and ... and Am(e) and T(e, tau), where R predicates are thematic roles, A predicates are adverbial or locative modifiers, and T predicates are temporal relations. The translation proceeds in five stages.

First, identify the core lexical predicate Verb(e). Second, collect role conjuncts into a dependent role record. Third, collect adverbial and locative predicates into a vector of modifiers and compute its length n : Nat. Fourth, translate temporal predicates into proposition-level or process-level temporal operators. Fifth, discharge the event variable and construct the dependent-type term.

For example, exists e. butter(e) and Agent(e, John) and Theme(e, toast) and slowly(e) and in(e, bathroom) and at(e, noon) becomes at_T(noon, butter(2)(slowly, in(bathroom), John, toast)). No event variable remains in the output. The semantic work of the original formula is distributed among the natural-number index, the modifier vector, the ordered role arguments, and the temporal operator.

## 6. Argument Omission and Existential Inference

Argument omission is one of the strongest motivations for event-based analyses. From John ate, speakers commonly infer that John ate something; from John read for an hour, they may infer that there was reading material; from John swept, the object or area may remain contextually underspecified. A uniform event variable can support such inferences by existential closure over missing role predicates, but this uniformity obscures important lexical differences.

The dependent-type replacement uses lexically governed omission schemas. A verb may specify a silent argument policy: obligatory, optional-existential, context-recoverable, incorporated, or absent. The rule for eat is optional-existential because the omitted object introduces a witness of type Food. The rule for arrive marks the theme role as absent rather than omitted. The rule for sweep may introduce either an affected surface or an affected object depending on constructional context. These distinctions are encoded in the verb's frame type rather than inferred from the existence of an event token.

Formally, optional-existential omission is represented by Sigma types. If V : A -> Option B -> Truth and V has the omission policy existential(B), then V(a, none) entails Sigma b : B. V(a, some b). This reproduces the relevant inference without assuming that all missing arguments are recoverable as thematic predicates of an event.

## 7. Thematic Roles without Event Conjuncts

Thematic roles are preserved as typed fields rather than event predicates. This shift has three advantages. First, role compatibility becomes type-checkable. A role record for butter can require an agent capable of intentional action and a theme that is a spreadable or surface-like object. Second, optional roles can be represented directly by option types. Third, cross-role dependencies can be stated explicitly: the type of result state may depend on the theme, and the type of instrument may depend on the action class.

The resulting role structure is not less expressive than neo-Davidsonian role conjunction. It can still represent agents, themes, patients, recipients, instruments, goals, sources, locations, and manners. The difference is that roles are no longer predicates of an event variable; they are fields in a typed frame that composes with the lexical predicate. This makes the role inventory available for automated checking and for construction-specific inference.

## 8. Time, Aspect, and Event Quantity

Temporal modification is treated by operators over propositions, processes, or states. Simple punctual location can be represented as at_T(t, P), and interval inclusion as during_T(i, P). Progressive aspect requires a process-level representation: progressive_T(i, Process(V, frame)) need not entail Culminated(V, frame). Perfect aspect can be represented as a relation between a prior culmination or state transition and a reference interval.

Event quantity is handled separately from ordinary predication. Sentences such as John knocked twice or Mary visited Paris three times require countable occurrences. The framework introduces EpisodeOf(P) only under counting, iteration, or anaphoric pressure. Twice(P) can be modeled as Sigma xs : Vec(EpisodeOf(P), 2). Disjoint(xs), where Disjoint ensures that the counted episodes are not merely duplicate descriptions of the same occurrence. Thus, event tokens appear as derived witnesses in counting constructions, not as universal arguments of every verb.

This selective introduction solves the event-number problem. A single accomplishment may contain many subevents, and different descriptions may count differently. By tying episode witnesses to a predicate P and a granularity condition, the framework avoids assuming that the world comes pre-partitioned into one canonical event inventory.

## 9. Causation and Resultatives

Causation and result states are often treated as event relations: an event of acting causes a result event or result state. The dependent-type alternative represents them as typed transitions. A state transition has the form Transition(object, state_scale, source_state, target_state). A causal predicate then relates an agent or causing condition to that transition: Cause(causer, Transition(x, scale, s1, s2)).

For John broke the vase, the translation is not exists e. break(e) and Agent(e, John) and Theme(e, vase). Instead, it is Cause(John, Transition(vase, integrity_scale, intact, broken)), with lexical constraints specifying the relevant state scale. For John hammered the metal flat, the result phrase flat supplies the target state: Cause(Hammering(John, metal), Transition(metal, shape_scale, not_flat, flat)). The prototype now makes this scale assignment explicit through a small state lexicon: broken and intact inhabit an integrity scale, flat, not_flat, round, and straight inhabit a shape scale, open and closed inhabit an access scale, solid, liquid, melted, and frozen inhabit a phase scale, and color resultatives such as red inhabit a color scale. It also supplies a lexical pre-state where this is safe: broken is reached from intact, flat from not_flat, open from closed, wet from dry, and so on; open-ended target states such as red retain an unknown source state. In the implementation this lexicon is structured as entries containing a scale, an optional default source state, and a source policy, rather than as unrelated string tables. This preserves the event-semantic insight that resultatives encode change, but it represents change directly rather than through an event variable.

The same strategy extends to accomplishments, achievements, and caused-motion constructions. The semantic core is a transition in a typed state or location space; the causing activity may be represented as a process if aspectual modification requires it.

## 10. Automation and Computational Implementation

The decomposition yields a practical translation pipeline. A parser or annotation layer identifies the core predicate, role predicates, modifiers, temporal relations, aspectual morphology, quantity expressions, result phrases, and causal constructions. The compiler then emits a dependent-type term using a small inventory of constructors: Pi-indexed verb families, role records, Sigma witnesses, option types, temporal operators, process constructors, transition constructors, and episode vectors.

Unlike a purely event-based compiler, the proposed system can preserve typing information during translation. It can detect an ill-typed instrument, distinguish absent from omitted arguments, prevent accidental event counting where no count operator is present, and encode result states as typed targets. The output is therefore suitable not only for semantic representation but also for automated reasoning, theorem proving, and controlled natural-language interfaces.

## 11. Prototype Implementation and Verification

The current prototype implements the translation strategy as a small compiler from a JSON representation of neo-Davidsonian conjunctions into two synchronized outputs. The first output is a compact formula string intended for inspection, for example at_T(noon, butter(2)(slowly, in(bathroom), John, toast)). The second output is a structured abstract syntax tree (AST) intended for type checking and later export to a proof assistant. This division is important because a string can be persuasive while still hiding malformed structure; the AST makes the translation auditable.

The AST currently contains six term forms. An application term represents a dependent verb-family application and stores the verb, the surface modifier list, a normalized modifier_vector with explicit tail lengths, the natural-number modifier count, ordered arguments, and a role_frame that preserves thematic labels and lexical role types such as Agent : Entity and Theme : Readable after the event variable has been discharged. A sigma term represents a lexically licensed implicit argument, as in Sigma x_theme : Food. eat(0)(John, x_theme). A repeat term represents event counting, as in repeat(2, knock(0)(John)). A time term represents temporal modification as a proposition-level operator. Transition and cause terms represent causal-resultative structure, requiring the result component to be a typed transition with an Entity theme, a StateScale, and State-valued source and target states rather than an arbitrary proposition.

The implementation also contains a shallow type checker. It verifies that the modifier count in an application agrees with the number of modifiers, that the normalized modifier_vector has the same length and order and well-formed tail-length indices, that the role_frame values match the ordered arguments in canonical thematic order, that role_frame types match the generated function argument types, that sigma bodies have propositional type, that repetition counts are positive natural numbers, that time operators are recognized, that transitions have the type TransitionT, that a transition target state is known, that the state scale matches the target state inferred from the lexical state map and any known source state, that known source and target states in a transition differ, and that the effect of Cause has type TransitionT. This type checker is intentionally modest: it does not yet prove the full semantic validity of the analysis. Its role is to prevent malformed intermediate representations from being silently rendered as well-formed-looking formulas.

Well-typed ASTs can now be exported to a shallow proof-assistant embedding. The Lean-style exporter renders a sigma witness as Exists fun x_theme : Food => (eat 0 mods_nil John x_theme), while the Coq-style exporter renders the same structure as exists x_theme : Food, (eat 0 mods_nil John x_theme). Non-binding constructors use a shared prefix notation, for example repeat 2 (knock 0 mods_nil John) and Cause John (Transition vase integrity_scale intact broken). The exporter now propagates lexical witness types beyond the eat example: John read introduces x_theme : Readable and read : forall n : nat, ModifierSeq n -> Entity -> Readable -> Prop, while John drank analogously introduces Drinkable. Overt objects of these verbs use the same lexical type, so Mary read the book declares book : Readable, records the Theme role as Readable in the AST, and annotates the exported example as Prop rather than PropT. The explanatory lexical_signature and dependent_type_principle fields use the same refinement, rendering read as ADV^n -> e -> Readable -> t rather than as a generic ADV^n -> e -> e -> t. The shallow interface defines PropT as an alias of Prop, so temporal operators such as at_T can scope over both ordinary PropT predicate-family outputs and existential propositions introduced by lexical omission. Export is deliberately refused for ill-typed ASTs and for module-level declaration conflicts such as reusing one constant at incompatible types, one verb at incompatible non-modifier argument types, or one role frame whose typed entries no longer match the exported function signature. Thus the proof-assistant boundary is guarded by the same structural checks used by the translator.

The exporter also generates complete interface scaffolds rather than isolated expressions. The generated Lean and Coq files introduce shallow constants for Entity, Food, State, StateScale, TransitionT, the example individuals, the predicate constructors, repetition, temporal operators, Transition, and Cause, while defining PropT as a shallow truth-type alias. They then define one example term for each checked translation and include proof-assistant-style inspection commands (#check in Lean style and Check in Coq style). Resultative examples now separate ordinary individuals from states and state scales: vase is exported as Entity, integrity_scale is exported as StateScale, intact and broken are exported as State, and Transition has type Entity -> StateScale -> State -> State -> TransitionT. This stage is still a shallow embedding, but it changes the engineering status of the project: the output is now a stable file-level artifact that can be refined into a genuine proof-assistant development. Coq is not used as the implementation language of the translator. Rather, Rocq/Coq is used as an optional boundary validator: when it is available, the repository-level verification command compiles the generated Coq scaffold with coqc to confirm that the exported terms are acceptable to an external dependent-type checker. In the current environment this check succeeds under the Rocq Prover, version 9.0.1.

The scaffold now separates entity-denoting arguments from Luo-Shi style predicate modifiers. In a sentence such as John buttered the toast in the bathroom with a knife, the individual arguments John and toast are exported at type Entity, while in_bathroom and with_knife are exported at type Adv, with Adv represented in the shallow Coq interface as (Entity -> PropT) -> Entity -> PropT. The generated verb type is now butter : forall n : nat, ModifierSeq n -> Entity -> Entity -> PropT, and the concrete modifiers are supplied as an indexed sequence such as mods_cons 1 in_bathroom (mods_cons 0 with_knife mods_nil), which has type ModifierSeq 2. The AST stores and checks the same vector shape before export; it also records modifier_roles, distinguishing in(bathroom) as a Location-like Adv, with(knife) as an Instrument-like Adv, and ordinary adverbs as Manner-like Adv values, and rejects metadata that labels with(knife) as a Location modifier. Directionals behave similarly: John went from home to school exports from_home/to_school as Source/Goal Adv constants. Each modifier-role record now contains a surface_lexicon audit object that preserves the original modifier string and its normalized proof-assistant constant, for example in(bathroom) -> in_bathroom and with(knife) -> with_knife, together with the Adv type, semantic role, and source module. The semantic-role choice is now supplied by a shared surface-lexicon table rather than by an ad hoc rule inside the main translator, so role classification and name normalization are tested as one lexical boundary. The checker rejects a mismatch between the displayed modifier and the exported constant. The Coq boundary checks the corresponding length invariant again. This correction is conceptually important in two ways: an automatic translator is not trustworthy if it erases the semantic distinction between modifiers and individuals, and it is also not adequate if the same lexical verb receives incompatible shallow declarations merely because different examples contain different numbers of modifiers.

The fallback natural-language parser now also recognizes simple object-final result phrases using the same state-scale lexicon. Thus John hammered the metal flat is not analyzed with a single entity constant metal_flat. Instead, metal remains an Entity theme, flat is introduced as a State, shape_scale is introduced as a StateScale, and the checked term is Cause(john, Transition(metal, shape_scale, not_flat, flat)). Mary painted the door red is handled analogously with color_scale, but because the current lexicon does not select a unique pre-red state, the source remains unknown_state. The pipeline now exposes a result_state_lexicon audit field recording, for each result target, the target state, its scale, its default source state when available, and whether the source was supplied by a lexical pre-state or left unknown by policy. Unknown-source cases are also surfaced as non-fatal diagnostics warnings: they can pass the structural and Coq/Rocq checks while still alerting the user that the state-transition source is lexically underspecified. The warning layer now distinguishes explicitly allowed unknown sources, derived scales with no known lexical pre-state, and states currently licensed only as transition sources. This is still a shallow constructional heuristic, but it removes a concrete source of overgeneration: the parser can no longer silently erase a result adjective into an object name when the adjective is already known as a typed result state.

The same state lexicon now protects copular result-state clauses from being overanalyzed as passive clauses with omitted agents. The vase is broken is rendered as holds_state(vase, integrity_scale, broken), and the door is open is rendered as holds_state(door, access_scale, open). These scaffolds introduce Entity, State, StateScale, and holds_state : Entity -> StateScale -> State -> Prop, but no Event, Agent, or Theme predicates. When a by-phrase is present, the agentive passive rule still applies: the vase was broken by John is rendered as break(john, vase). This separation is important because result states are one of the places where event semantics, passive morphology, and state predication can otherwise be collapsed into a single hidden-event analysis.

The prototype now also separates lexical change-of-state alternations from the generic fallback parser. The door opened is rendered as Change(Transition(door, access_scale, closed, open)), so door is the changing theme rather than an Agent of a one-place predicate. John opened the door is rendered as Cause(john, Transition(door, access_scale, closed, open)). John opened the door with a key is rendered as CauseWithInstrument(john, key, Transition(door, access_scale, closed, open)), preserving the instrumental role without introducing an event variable. The same construction handles the opposite access transition: the door closed becomes Change(Transition(door, access_scale, open, closed)). It has now been generalized from this access-scale example to other state-lexicon scales: the clothes dried becomes Change(Transition(clothes, moisture_scale, wet, dry)), John dried the clothes with a towel becomes CauseWithInstrument(john, towel, Transition(clothes, moisture_scale, wet, dry)), the water froze becomes Change(Transition(water, phase_scale, liquid, frozen)), John melted the ice becomes Cause(john, Transition(ice, phase_scale, solid, melted)), Mary cleaned the room becomes Cause(mary, Transition(room, cleanliness_scale, dirty, clean)), the tank emptied becomes Change(Transition(tank, content_scale, full, empty)), and John filled the glass becomes Cause(john, Transition(glass, content_scale, empty, full)). Life-scale examples show why frame licensing belongs in the lexical registration rather than in a free post-hoc role list: John died is licensed as Change(Transition(john, life_scale, alive, dead)), while Mary killed the plant with poison is licensed as CauseWithInstrument(mary, poison, Transition(plant, life_scale, alive, dead)); the plant killed is not accepted as the corresponding inchoative. The verb-to-state relation is now mediated by structured StateChangeVerbEntry records rather than a bare string table. These records have been moved into a separate state-change lexicon module, so the lexical inventory is maintained outside the parser rule that recognizes surface constructions. Each entry records the target state and whether inchoative, causative, and instrumental frames are licensed, and the pipeline exposes this registration as a state_change_verb_entry audit field. The AST also carries a surface_lexicon audit object for the surface verb and selected lemma, preserving mappings such as died -> die and froze -> freeze before the state-change entry is applied. The AST also carries an explicit frame field, and the checker uses the surface audit, the frame, and the registration as negative guards, rejecting internally malformed analyses whose surface lemma, registered verb, target state, or causer/instrument fields disagree. This is still a controlled lexical slice, not a full parser, but it is conceptually useful: it shows how causative/inchoative alternations can be represented through typed transitions and role-bearing constructors rather than through an all-purpose event argument.

The implementation now includes a first Parsons-style event-talk case, after the singing of the Marseillaise, John saluted the flag. The generated analysis preserves an event-semantics reference formula for comparison, but the checked replacement follows the Luo-Shi timed strategy: it introduces Time, before : Time -> Time -> Prop, sing : Entity -> Time -> Prop, and salute : Entity -> Entity -> Time -> Prop, then defines the translation as an existential formula over t_sing and t_salute. The AST binds the two time variables and verifies that before orders t_sing before t_salute. The generated Coq scaffold deliberately contains no Event declaration for this case. This test is narrow, but it is methodologically important because it shows how a construction apparently motivating event-to-event ordering can be refactored into typed temporal dependence and externally checked without a hidden event variable.

Two additional Parsons/Luo-Shi cases are now represented by construction-specific replacements. For Mary saw John leave, the checked scaffold introduces E : Prop -> Entity, leave : Entity -> Prop, and see : Entity -> Entity -> Prop, yielding see Mary (E (leave John)). The AST now records this composition explicitly: the perception predicate takes an Entity experiencer and an Entity object, the embedded predicate forms a Prop from John, and E maps that Prop into the object position. The embedded leaving proposition is therefore available as the object of perception without treating it as a Davidsonian event variable. The same nominalization path now accepts a checked embedded subject coordination: Mary saw John and Bill leave renders as see(Mary, E(and_T(leave(John), leave(Bill)))), and Mary saw John or Bill leave uses or_T inside the same E object. It also accepts a checked coordination of two complete embedded propositions: Mary saw John leave and Bill wave renders as see(Mary, E(and_T(leave(John), wave(Bill)))), with leave and wave declared separately at type Entity -> Prop. A further temporal complement case keeps the time dependence inside the proposition being nominalized: Mary saw John leave after Bill waved renders as see(Mary, E(exists t_main t_reference : Time. leave(John, t_main) and wave(Bill, t_reference) and before(t_reference, t_main))). In this case leave and wave have type Entity -> Time -> Prop, and the surface after relation is checked as an ordering of the reference time before the main time. The reference side can also be coordinated without introducing event inclusion: Mary saw John leave after Bill waved and Sue smiled renders as see(Mary, E(exists t_main t_reference_1 t_reference_2 : Time. leave(John, t_main) and and_T(wave(Bill, t_reference_1), smile(Sue, t_reference_2)) and before(t_reference_1, t_main) and before(t_reference_2, t_main))). Thus the perceived complement remains a proposition until the nominalizer maps it to the entity-denoting object expected by see. For In every burning, oxygen is consumed, the checked scaffold introduces Time and renders the sentence as forall x : Entity, forall t : Time, burn x t -> consume oxygen t. Its AST binds x : Entity and t : Time and checks that burn and consume both have type Entity -> Time -> Prop over the shared time variable. This avoids both a hidden Event type and an event-inclusion predicate such as IN(e,e'). These two tests sharpen the project criterion: a successful replacement must assign the right lexical and constructional types, not merely produce a Coq file that compiles.

The latest perception-complement refinement makes the temporal-relation replacement symmetric with respect to coordination. The main side of the perceived temporal proposition can now be coordinated just like the reference side: Mary saw John leave and Sue smile after Bill waved renders as see(Mary, E(exists t_main_1 t_main_2 t_reference : Time. and_T(leave(John, t_main_1), smile(Sue, t_main_2)) and wave(Bill, t_reference) and before(t_reference, t_main_1) and before(t_reference, t_main_2))). The checker no longer assumes a single t_main variable; it extracts all main-side and reference-side time variables and requires one before relation for every main/reference pair, with the direction determined by after or before. This is a small but important strengthening of the Luo-Shi-style replacement, because coordination is handled inside the time-indexed proposition rather than by manufacturing an event or entity for a coordinated phrase.

The same invariant now covers bilateral coordination. Mary saw John leave and Sue smile after Bill waved and Ann laughed binds two main times and two reference times, then requires four before constraints: each reference time must precede each main time for after, and the direction is reversed for before. This turns the temporal replacement into a structural obligation over the AST rather than a string-rendering convention, and it also exercises the surface lexicon's regular past-tense normalization of laughed to laugh inside the perception-complement rule.

The coordination arity has also been generalized beyond the binary case. Mary saw John leave and Sue smile and Ann laugh after Bill waved binds three main-side time variables and one reference time, renders the proposition with right-associated binary and_T, and checks three before constraints. Conversely, Mary saw John leave after Bill waved and Sue smiled and Ann laughed binds one main time and three reference times. The same n-ary boundary is now tested for before: three main clauses before one reference clause check before(t_main_i, t_reference), and one main clause before three reference clauses checks before(t_main, t_reference_i). Homogeneous temporal disjunction is handled by a branch-local scope policy rather than by flattening all time variables into one conjunction: Mary saw John leave or Sue smile after Bill waved renders as or_T(exists t_main_1 t_reference : Time. leave(John, t_main_1) and wave(Bill, t_reference) and before(t_reference, t_main_1), exists t_main_2 t_reference : Time. smile(Sue, t_main_2) and wave(Bill, t_reference) and before(t_reference, t_main_2)). The reference-side counterpart, Mary saw John leave after Bill waved or Sue smiled, is treated analogously. When both sides are disjunctive, as in Mary saw John leave or Sue smile after Bill waved or Ann laughed, the renderer builds the Cartesian set of branch-local temporal alternatives, yielding four scoped or_T branches rather than one flat existential conjunction. Mixed and/or timed coordination is now accepted under an explicit precedence policy: adjacent and-groups are formed first, and the resulting groups are folded by or_T with branch-local existential time binders. Thus Mary saw John leave and Sue smile or Ann laugh after Bill waved becomes an or_T whose first branch contains and_T(leave(John, t_main_1), smile(Sue, t_main_2)) with two reference-before-main constraints, and whose second branch contains laugh(Ann, t_main_3) with its own scoped reference time. Parenthesized and pragmatically marked alternative scope readings remain outside this controlled fragment. This keeps the proof-assistant interface binary while letting the AST represent natural-language lists of timed propositions as lists rather than as a fixed pair.

The argument-omission component has also been sharpened with a passive construction slice. For the toast was buttered by John, the checked replacement is butter(john, toast). For the toast was buttered, the checked replacement is exists x_agent : Entity. butter(x_agent, toast). The AST records toast : Entity as the surface subject but logical Patient, records either john : Entity from the by-phrase or an existential x_agent : Entity, records the finite passive auxiliary is, was, are, or were, and keeps the predicate type fixed as Entity -> Entity -> Prop with Agent before Patient. Surface morphology is now mediated by a separate surface-lexicon module rather than by the passive rule itself. That module supplies passive participle recognition and maps irregular participles to base predicate names, so John was seen by Mary exports see(mary, john), and the letter was written exports exists x_agent : Entity. write(x_agent, letter). The passive AST now exposes this step as a surface_lexicon audit object recording the original participle, the selected lemma, and the source module, and the type checker rejects a mismatch between the audit lemma and the exported predicate. The construction order gives the more specific Parsons/Luo-Shi burning rule priority over this broader passive recognizer, so In every burning, oxygen is consumed still receives the universal time-indexed analysis rather than a simple passive-agent analysis. This gives a small but important contrast with neo-Davidsonian role conjunction: the omitted role is represented by an ordinary typed existential over entities, not by an existential event with Agent and Theme predicates.

The specialized analyses are now mediated by a construction registry. A registered rule records a stable rule identifier, a human-readable label, the phenomenon it covers, the analyzer that recognizes the construction, and construction-specific Coq fragments that must not appear in the generated scaffold. For example, the Parsons/Luo-Shi replacements reject generated Coq that reintroduces a hidden Event declaration, the burning rule also rejects IN, and the passive omission rule rejects exported Agent and Theme role predicates. The registered-rule executor now stops before construction hygiene and Coq/Rocq validation if the construction-specific AST type check has already failed, marking the downstream stages as skipped. This registry turns a methodological warning into an executable check: proof-assistant acceptance is necessary, but not sufficient, unless the generated interface also respects the type-theoretic replacement promised by the construction.

The current perception-complement regression tests add the symmetric coordination boundary explicitly. They accept both Mary saw John leave after Bill waved and Sue smiled, where one main time is ordered against two reference times, and Mary saw John leave and Sue smile after Bill waved, where two main times are ordered against one reference time. In both directions the checker rejects an AST with a missing before relation before proof-assistant export, so a compiling Coq scaffold cannot hide an underconstrained temporal replacement.

Bilateral coordination is tested as the next boundary case: when both the perceived main proposition and its temporal reference are coordinated, the checker requires the full set of four ordered time pairs, rejects a malformed AST containing only three relations, and rejects a relation list whose length is correct but whose before arguments are ordered incorrectly for the surface connector.

The n-ary perception tests cover the next arity boundary: three main-side timed clauses and three reference-side timed clauses both compile to Coq/Rocq through right-associated and_T terms, while preserving one explicitly checked time variable per clause. A corresponding web/API regression checks that the same n-ary temporal perception analysis is exposed through the interactive page and JSON endpoint with the registered construction metadata, AST, dependent-type translation, and Coq status intact. The complementary web/API cases now check both sides of the disjunction policy: Mary saw John leave or Sue smile after Bill waved is verified as a branch-local or_T of time-indexed propositions, while mixed Mary saw John leave and Sue smile or Ann laugh after Bill waved is verified under the explicit and-before-or precedence policy. In both cases the parser must not silently convert temporal material into an Entity name and then export a compiling but wrong Coq scaffold.

The predicate-coordination tests add a focused regression boundary to this suite. They check that John walked and talked exports two Entity -> Prop predicates under and_T, that John walked or talked uses the same AST with or_T rather than a pseudo-object or_talked, that marked either/or forms such as John either walked or talked and Either John walked or talked keep john as the subject rather than john_either or either_john, that the paired both/and marker in John both walked and talked is likewise stripped only when it marks the first predicate rather than a sentence-initial coordinated subject, that Mary ran and jumped and the old dog walked and slept are lemmatized correctly, that trailing and fronted temporal modifiers scope over the conjunction rather than into the subject, that fronted or trailing non-temporal prepositional material such as In the park and single-word manner adverbs such as slowly remain shared Adv modifiers with ModifierSeq-indexed predicate types, that multiple shared modifiers preserve surface order in the generated ModifierSeq even when one modifier is fronted and another is trailing, that object coordination such as Mary visited Paris and London is routed to its own typed construction rather than captured by the predicate-coordination rule, and that malformed predicate or modifier types are rejected before Coq export.

The subject-coordination tests cover the complementary case in which two Entity subjects share one predicate. John and Mary walked and Both John and Mary walked render as and_T(walk(john), walk(mary)); John or Mary walked renders as or_T(walk(john), walk(mary)); and John and Mary walked in the park yesterday keeps in(park) as a shared Adv modifier and yesterday as an outer time operator. The transitive subject-coordination tests add an explicit shared object field: John and Mary ate bread renders as and_T(eat(john, bread), eat(mary, bread)) with bread : Food, John or Mary drank water renders as or_T(drink(john, water), drink(mary, water)) with water : Drinkable, and John and Mary ate bread in the park yesterday preserves both the object type and the shared Adv/time structure.

The object-coordination tests cover the remaining mirror image for a shared subject and shared transitive predicate. Mary visited Paris and London renders as and_T(visit(mary, paris), visit(mary, london)) rather than visit(0)(mary, paris_and_london). Mary visited both Paris and London strips the object-level both marker before the first object, and Mary visited Paris or London uses or_T over the two typed object applications. With shared Adv and time material, Mary visited Paris and London in the park yesterday renders as at_T(yesterday, and_T(visit(1)(in(park), mary, paris), visit(1)(in(park), mary, london))). The tests also keep this construction separate from same-subject VP coordination, so the second object is not mistaken for the object of an unexpressed second verb.

The transitive predicate-coordination tests check the next VP-level case. John ate bread and drank water exports two typed transitive predicates under and_T, with bread : Food, water : Drinkable, eat : Entity -> Food -> Prop, and drink : Entity -> Drinkable -> Prop. John ate bread or drank water keeps the same typed objects and uses or_T rather than forming bread_or_drank_water, John either ate bread or drank water keeps the same subject and objects rather than constructing john_either, and John both ate bread and drank water keeps john rather than john_both while preserving the Food and Drinkable object types. Mary read a book and wrote a letter checks that a lexical theme such as book : Readable can be coordinated with an ordinary Entity object. The temporal tests verify that sentence-final and sentence-initial time both scope over the whole conjunction, while In the park John ate bread and drank water, John ate bread and drank water in the park, John ate bread and drank water quickly, John ate bread and drank water quickly in the park, and Quickly John ate bread and drank water in the park verify that locations and manner adverbs are shared Adv modifiers rather than malformed subjects or objects. The negative test keeps Mary visited Paris and London outside the VP-coordination rule. A malformed object or modifier type is rejected because the predicate type no longer matches the object's declared type or the shared modifier is no longer Adv.

The declaration-hygiene tests now separate repeated semantic occurrence from repeated shallow declaration. John walked and talked slowly slowly keeps two slowly modifiers in the indexed ModifierSeq, and John walked and talked yesterday yesterday keeps two nested temporal operators, but each corresponding Coq constant is declared once. John ate bread and ate bread likewise keeps two conjuncts while declaring bread : Food and eat : Entity -> Food -> Prop once. By contrast, John ate bread and drank bread is rejected by the internal AST type check because the same surface constant would need the incompatible lexical types Food and Drinkable; the registered-rule executor therefore skips Coq/Rocq validation and reports the type-checking boundary directly.

The fallback lemmatization tests now also cover ordinary past-tense and irregular motion examples such as chased -> chase, passed -> pass, flew -> fly, ran -> run, slept -> sleep, and wrote -> write, so a supported simple-sentence analysis no longer exports a truncated predicate name before the Coq boundary check.

The fallback subject splitter now consults the same surface-lexicon boundary before choosing the predicate. This permits a narrow class of adjective+noun subject phrases when the following word is a known verb form: a black cat sits on a mat becomes sit(1)(on(mat), black_cat), the old dog chased a cat becomes chase(0)(old_dog, cat), and the little bird flew from the tree to the roof becomes fly(2)(from(tree), to(roof), little_bird). The rule is intentionally conservative; it improves common simple inputs without claiming to provide a full syntactic parser.

The fallback parser also recognizes a small shared class of temporal adverbs, currently today, tomorrow, and yesterday. These words are emitted as temporal atoms such as at(e, yesterday), so Mary admired the painting yesterday is translated as at_T(yesterday, admire(0)(mary, painting)) rather than as admire(0)(mary, painting_yesterday). The same boundary is used inside prepositional phrases, preventing a sentence such as a cat sits on a mat yesterday from producing the modifier on(mat_yesterday).

This temporal boundary now extends to a small class of multi-word temporal phrases. Last night is normalized as last_night and this morning as this_morning before event-formula translation. Consequently, Mary admired the painting last night becomes at_T(last_night, admire(0)(mary, painting)), and John walked to school this morning becomes at_T(this_morning, walk(1)(to(school), john)) rather than a locative goal to(school_this_morning). The same rule applies sentence-initially: Yesterday Mary admired the painting becomes at_T(yesterday, admire(0)(mary, painting)) rather than assigning the subject yesterday_mary. Existing sequences such as at noon yesterday remain represented by nested time operators, at_T(yesterday, at_T(noon, ...)).

The time layer now also recognizes a restricted set of prepositional time phrases in both fronted and sentence-final positions. At noon Mary admired the painting, including the punctuated variant At noon, Mary admired the painting, becomes at_T(noon, admire(0)(mary, painting)); At noon yesterday Mary admired the painting becomes at_T(yesterday, at_T(noon, admire(0)(mary, painting))); In the morning John walked to school becomes during_T(morning, walk(1)(to(school), john)); On Monday Mary visited Paris becomes at_T(monday, visit(0)(mary, paris)); and Mary admired the painting in the morning becomes during_T(morning, admire(0)(mary, painting)). The restriction to known temporal nouns is deliberate: the fallback parser should not reinterpret arbitrary locative phrases such as in the bathroom as temporal operators. This boundary is especially important for at: Mary waited at noon becomes at_T(noon, wait(0)(mary)), whereas Mary waited at the station becomes wait(1)(at(station), mary) and John buttered the toast at the table becomes butter(1)(at(table), john, toast).

The corresponding fronted-modifier case is now handled on the Adv side rather than by subject concatenation. In the bathroom Mary buttered the toast with a knife becomes butter(2)(in(bathroom), with(knife), mary, toast), With a knife John buttered the toast in the bathroom becomes butter(2)(with(knife), in(bathroom), john, toast), and From home John walked to school becomes walk(2)(from(home), to(school), john). A locative subject example such as On the mat a cat sits becomes sit(1)(on(mat), cat), and At the station Mary waited becomes wait(1)(at(station), mary). The same boundary now keeps short multi-word PP objects together: In the old bathroom Mary buttered the toast becomes butter(1)(in(old_bathroom), mary, toast), With a sharp knife John buttered the toast becomes butter(1)(with(sharp_knife), john, toast), and At the train station Mary waited becomes wait(1)(at(train_station), mary). This improvement is small but directly tied to the Luo-Shi analysis: fronted prepositional material is typed as Adv and added to the indexed modifier sequence, not reified as an Entity constant such as in_bathroom_mary.

The same fallback layer now treats simple copular location sentences as stative location predications rather than action predicates with Agents. A cat is on a mat becomes be(1)(on(mat), cat), the old dog is near the door becomes be(1)(near(door), old_dog), and In the park the old dog is near the door becomes be(2)(in(park), near(door), old_dog). The subject of such a locative state is recorded as Theme in the intermediate event-style formula, so the dependent-type output does not claim that the located entity is an Agent. This rule is deliberately ordered after the specialized construction registry: the vase is broken still receives the typed stative-result analysis holds_state(vase, integrity_scale, broken), and the toast is buttered still receives the passive omitted-agent analysis rather than a generic copular-location fallback.

Ordinary copular property clauses now receive their own typed construction as well. Mary is happy becomes holds_property(mary, happy), with happy declared at type Property rather than Entity or State. Temporal modification composes outside that property assertion, so Mary was happy yesterday becomes at_T(yesterday, holds_property(mary, happy)). Negation and degree modification are now represented structurally rather than by inventing fresh atomic properties: Mary is not happy becomes not_T(holds_property(mary, happy)), Mary is very happy becomes holds_property(mary, degree_property(very, happy)), and Mary is not very happy combines both wrappers. Simple copular coordination is now structural as well: Mary is happy and calm becomes and_T(holds_property(mary, happy), holds_property(mary, calm)), while Mary is happy and very calm keeps the degree operator on the second conjunct. The construction is deliberately lower priority than the typed state and passive analyses: the door is red remains holds_state(door, color_scale, red), because red is a registered State; the door is not red becomes not_T(holds_state(door, color_scale, red)) rather than not_red : Property; the door is red and open becomes and_T(holds_state(door, color_scale, red), holds_state(door, access_scale, open)) rather than red_and_open : Property; and the toast is buttered remains an omitted-agent passive. This prevents the fallback layer from erasing distinctions among State, Property, Degree, coordination, and passive participial predication while still giving common non-state adjectives a checked dependent-type target.

The same proposition-level treatment has been extended to simple do-support negation. John did not walk is compiled as not_T(walk(0)(john)), and John does not walk slowly in the park becomes not_T(walk(2)(slowly, in(park), john)); the positive-clause AST is built first and then wrapped in a structured not node. Transitive examples preserve lexical object types, so John did not eat bread wraps eat(0)(john, bread) with bread : Food. The implementation now also covers a narrow right-branch coordination pattern: John walked and did not talk becomes and_T(walk(john), not_T(talk(john))), and John ate bread and did not drink water becomes and_T(eat(john, bread), not_T(drink(john, water))) with bread : Food and water : Drinkable. The same right-branch rule now supports disjunction: John walked or did not talk becomes or_T(walk(john), not_T(talk(john))), and John ate bread or did not drink water becomes or_T(eat(john, bread), not_T(drink(john, water))). The same pattern preserves the earlier treatment of temporal and adverbial material: Yesterday John walked and did not talk places at_T outside the typed conjunction, while John walked and did not talk in the park keeps in(park) as a shared Adv modifier inside both coordinates. Clear contrastive but coordination is now handled as the mirror image of the right-branch pattern: John did not walk but talked becomes and_T(not_T(walk(john)), talk(john)), and John did not eat bread but drank water becomes and_T(not_T(eat(john, bread)), drink(john, water)). Shared modifiers are preserved for those contrastive readings as well: John did not walk but talked in the park becomes and_T(not_T(walk(1)(in(park), john)), talk(1)(in(park), john)), and John did not eat bread but drank water in the park keeps bread : Food, water : Drinkable, and in(park) : Adv on both branches. Branch-local modifiers are now represented by independent ModifierSeq indices rather than by object-name concatenation: John did not walk in the park but talked becomes and_T(not_T(walk(1)(in(park), john)), talk(0)(john)), John did not eat bread in the park but drank water becomes and_T(not_T(eat(1)(in(park), john, bread)), drink(0)(john, water)), and John did not eat bread in the park but drank water quickly becomes and_T(not_T(eat(1)(in(park), john, bread)), drink(1)(quickly, john, water)). Fronted shared Adv material is now copied into both branch-local sequences, so In the park John did not eat bread slowly but drank water quickly becomes and_T(not_T(eat(2)(in(park), slowly, john, bread)), drink(2)(in(park), quickly, john, water)). Branch-internal time is represented on the same clause-local structure: John did not eat bread yesterday but drank water quickly becomes and_T(not_T(at_T(yesterday, eat(0)(john, bread))), drink(1)(quickly, john, water)). The same step adds a surface-lexicon gate for transitive coordination: both coordinated verbs must be licensed as transitive before the rule may consume object material, so walk in the park and talk quickly cannot be miscompiled as Entity-object applications. Scope-ambiguous coordinated negation, such as John did not walk and talk, is now represented by two typed readings rather than rejected or collapsed: a wide-negation reading not_T(and_T(walk(john), talk(john))) and a distributed-negation reading and_T(not_T(walk(john)), not_T(talk(john))). This ambiguity rule now uses the same branch-local modifier machinery before object interpretation: John did not walk slowly and talk quickly produces the two readings over walk(1)(slowly, john) and talk(1)(quickly, john), while John did not eat bread slowly and drink water quickly keeps bread : Food and water : Drinkable as objects and slowly/quickly as Adv modifiers rather than constructing bread_slowly or water_quickly as pseudo-entities. Branch-local time is preserved in the same reading structure, so John did not walk yesterday and talk today scopes the two alternative negation readings over at_T(yesterday, walk(0)(john)) and at_T(today, talk(0)(john)) rather than moving both times to a single undifferentiated sentence-level modifier. Fronted shared material is likewise kept out of the subject: Yesterday John did not walk and talk wraps both readings in at_T(yesterday, ...), and In the park John did not walk slowly and talk quickly copies in(park) into both branch-local ModifierSeq arguments while preserving john as the Entity subject. The fronted prefix is peeled iteratively in this construction, so In the park yesterday John did not walk and talk also keeps john as the subject, in(park) as shared Adv, and yesterday as outer time. Repeated do-support negation across both branches, as in John did not walk and did not talk, is treated as the explicit distributed form and_T(not_T(walk(john)), not_T(talk(john))); the corresponding transitive case keeps bread : Food and water : Drinkable, and fronted material composes in the same way. When the repeated surface connective is or, as in John did not walk or did not talk, the translator preserves it as or_T(not_T(walk(john)), not_T(talk(john))) rather than forcing an and-like distributed reading. Negated disjunction is kept as a single checked reading: John did not walk or talk becomes not_T(or_T(walk(john), talk(john))), and John did not eat bread or drink water becomes not_T(or_T(eat(john, bread), drink(john, water))) rather than introducing pseudo-objects such as or_talk or bread_or_drink_water. This is an intentionally conservative automation choice: genuine ambiguity should be made explicit instead of compiled to a plausible but wrong single dependent-type formula.

The same construction-specific approach now covers a narrow but useful predicate-coordination boundary. John walked and talked is no longer analyzed as a transitive fallback with the pseudo-object and_talked. It is rendered as and_T(walk(john), talk(john)), with walk and talk both declared at type Entity -> Prop. The same AST now handles same-subject disjunction: John walked or talked renders as or_T(walk(john), talk(john)), not as walk(0)(john, or_talked). Marked either/or variants strip either as a surface coordination marker, so John either walked or talked and Either John walked or talked also keep john as the Entity subject; the paired both/and form John both walked and talked is treated the same way for conjunction, while sentence-initial both remains outside this rule because it may mark coordinated subjects. Temporal material scopes outside the conjunction, so John walked and talked yesterday and Yesterday John walked and talked both become at_T(yesterday, and_T(walk(john), talk(john))) rather than introducing a subject such as yesterday_john. Non-temporal modifier material is treated differently in either fronted or trailing position: In the park John walked and talked, John walked and talked in the park, John walked and talked slowly, and Slowly John walked and talked all use shared Adv modifiers and ModifierSeq-indexed predicates rather than a subject, object, or Theme formed from the modifier string. Multiple shared modifiers preserve surface order: John walked and talked slowly in the park uses the sequence slowly, in(park), while John walked and talked in the park slowly uses in(park), slowly. The AST records the shared subject, the two surface predicates, their lemmatized names, shared Adv modifiers, the connective and_T or or_T, and any time modifiers; the checker rejects a malformed predicate whose type is not Entity -> Prop or, when modifiers are present, not ModifierSeq-indexed. The rule is deliberately restricted to same-subject intransitive predicate coordination. Object coordination such as Mary visited Paris and London remains outside this construction and is now handled by its own object_coordination rule rather than by a fallback Theme constant paris_and_london. This boundary is methodologically important: the translator may add constructions incrementally, but each construction must state what it licenses and what it refuses to license.

The complementary subject-coordination rule now covers the narrow case in which two Entity subjects share one predicate. John and Mary walked is rendered as and_T(walk(john), walk(mary)), and Both John and Mary walked receives the same output rather than the fallback constant both_john_and_mary. Disjunction is also typed: John or Mary walked becomes or_T(walk(john), walk(mary)). Shared modifiers are not folded into subject names, so John and Mary walked in the park yesterday becomes at_T(yesterday, and_T(walk(1)(in(park), john), walk(1)(in(park), mary))). The next step extends the same idea to a shared transitive object: John and Mary ate bread becomes and_T(eat(john, bread), eat(mary, bread)), with bread exported at type Food and eat at type Entity -> Food -> Prop. With shared modifiers and time, John and Mary ate bread in the park yesterday becomes at_T(yesterday, and_T(eat(1)(in(park), john, bread), eat(1)(in(park), mary, bread))). This removes another fallback-style pseudo-subject without reintroducing event variables or thematic-role predicates.

The coordination layer has also been extended one step further to same-subject transitive verb phrases. John ate bread and drank water is rendered as and_T(eat(john, bread), drink(john, water)), not as eat(0)(john, bread_and_drank_water). John ate bread or drank water uses the same typed object split with or_T(eat(john, bread), drink(john, water)), not bread_or_drank_water. The marked form John either ate bread or drank water is normalized the same way and keeps john rather than john_either as the subject; John both ate bread and drank water similarly keeps john rather than john_both. The rule preserves lexical object types: bread is Food, water is Drinkable, and the generated Coq scaffold gives eat and drink correspondingly different argument types. A mixed lexical example such as Mary read a book and wrote a letter keeps book at type Readable while letter remains Entity. As with intransitive coordination, sentence-final and sentence-initial time scope over the whole conjunction: John ate bread and drank water yesterday and Yesterday John ate bread and drank water both become at_T(yesterday, and_T(eat(john, bread), drink(john, water))). Fronted and trailing locations and manner adverbs are shared Adv modifiers across both conjuncts: In the park John ate bread and drank water and John ate bread and drank water in the park both become and_T(eat(1)(in(park), john, bread), drink(1)(in(park), john, water)), while John ate bread and drank water quickly becomes and_T(eat(1)(quickly, john, bread), drink(1)(quickly, john, water)). When both a manner adverb and location occur, the two modifiers are stored in the observed order and the Coq scaffold emits the corresponding nested mods_cons spine. In all cases, bread and water keep their Food and Drinkable types. The construction is still intentionally narrow; it does not analyze all coordination phenomena, and it continues to leave Mary visited Paris and London to object_coordination rather than treating London as the object of an unexpressed second verb.

The same coordination exporters now perform declaration de-duplication after semantic construction but before Coq rendering. This matters because a repeated modifier, repeated time expression, or repeated conjunct is a semantic fact about the formula, whereas a duplicate Parameter line is merely an artifact of the shallow embedding. Identical declarations are therefore emitted once, while incompatible declarations remain errors. The distinction is important for automation: a successful Coq check should not depend on accidental uniqueness of surface words, but it should still expose cases where the lexical typing itself is underspecified or inconsistent.

The same surface boundary has been extended to simple count phrases. In addition to once, twice, and thrice, the fallback parser recognizes word or digit time(s) expressions and emits a count atom such as times(e, 3). The existing dependent-type AST then renders this as repeat(3, ...). Thus Mary visited Paris three times and Mary visited Paris 3 times both become repeat(3, visit(0)(mary, paris)) rather than visit(0)(mary, paris_three_times) or visit(0)(mary, paris_3_times), and a cat sits on a mat 2 times becomes repeat(2, sit(1)(on(mat), cat)) rather than a malformed locative modifier on(mat_2_times).

The deterministic verification command now runs the package-build smoke check with the active Python environment's local build tooling, avoiding build isolation for this smoke test so that an otherwise complete offline run is not misreported as a semantic or proof-assistant failure merely because the runner cannot download setuptools.

The manuscript artifact is now part of the same reproducibility discipline. The Markdown source is treated as authoritative, and the Word manuscript is rebuilt by a deterministic DOCX synchronizer. A shared paper-markdown module parses table rows, headings, list items, emphasis, code spans, and visible link text so that the DOCX generator and the DOCX synchronization checker do not maintain separate Markdown rules. The checker validates that the generated Word text follows the Markdown source order and reports missing or out-of-order blocks, including table cells. A dedicated paper-DOCX test module covers negative synchronization cases, inline formatting extraction, and an end-to-end fixture that generates a DOCX from rich Markdown, checks that the Word file remains synchronized, and inspects the generated Word runs for bold, italic, code-font, and link-text behavior. The repository-level verification command now exposes a --require-docx gate, and the continuous-integration workflow installs the document extra before running it, so Word-generation tests cannot be accidentally mistaken for completed checks when python-docx is absent. This documentation pipeline is not part of the semantic theory itself, but it matters methodologically: it keeps the paper, implementation, and proof-assistant boundary checks synchronized as the prototype evolves.

The same architecture can be exposed as an interactive web pipeline. A user-facing interface would accept a natural-language sentence, display the event-semantics analysis, translate it into the dependent-type AST and readable formula, generate a Coq scaffold, and report whether the internal type check and optional Coq/Rocq boundary check succeed. The present implementation contains a small rule-based backend slice for controlled sentences such as John ate, John knocked twice, and John broke the vase. It now also includes a conservative fallback parser for simple unlisted sentences; for example, a cat sits on a mat is analyzed as sit(e), Agent(e, cat), and on(e, mat), then translated as sit(1)(on(mat), cat). Quantifier-scope cases are handled separately rather than forced into this fallback: some boy loves some girl is represented by two checked readings, one with the boy existential taking wider scope and one with the girl existential taking wider scope. The internal AST records those readings as scope-order objects with variables and predicate types, with boy and girl assigned predicate types Entity -> Prop and love assigned type Entity -> Entity -> Prop rather than being mediated by an Event argument, Agent, or Theme declaration. A prior browser prototype for the project already separated single-event, nested-perception, and temporal-After patterns; its main value is as a user-interface and rule-classification sketch. The current implementation keeps that insight but makes the stages auditable through typed Python analyses, explicit ASTs, and Coq/Rocq boundary checks. The local web demo presents these stages and the final conclusion as separate panels over the same verified backend. This slice is not a general natural-language parser, but it establishes the desired diagnostic structure: parsing failures, AST type failures, and proof-assistant boundary failures are reported as distinct stages rather than collapsed into a single error. The Coq/Rocq check certifies the well-typedness of the exported formal scaffold; it does not by itself prove that a natural-language sentence has no additional readings or that the parser has selected the only correct analysis.

The web/API layer now makes that diagnostic structure explicit. Each analysis response and its API Contract panel carry schema_version analyze.v1, plus compact diagnostics with a machine-readable failure_stage field, recovery_hint, structured recovery_actions, and non-fatal warnings. Successful analyses expose no recovery action; failures distinguish input, parsing, type_check, construction_hygiene, and coq_check stages. Successful analyses with warnings are reported in the status banner as verified with warnings, so the interface does not confuse a passed proof-assistant boundary check with a fully specified lexical state model. The diagnostics object also exposes manual_repair_required and lexicon_patch_draft_count, making human-gated lexical repair visible at the same level as the warning. The web page renders the same actions in a Next Steps panel, with stable data-action-kind attributes and next-step--kind CSS classes so browser tests or later interface buttons can target the suggested repair without parsing prose. It also renders the type_check object in a dedicated Type Check panel, so construction-specific AST failures such as an unlicensed state-change frame expose their exact error list to the user. It renders the result_state_lexicon field in a dedicated Result State Lexicon panel and lifts modifier role metadata to a Modifier Role Audit panel, so resultative analyses display the target state, scale, source state, and source policy while modifier analyses display Adv roles such as Location and Instrument together with the surface_lexicon fields that map in(bathroom) to in_bathroom and with(knife) to with_knife, without requiring the reader to inspect the raw AST. Non-fatal warnings are now mirrored in a separate Semantic Warnings panel with stable data-warning-kind attributes, suggested_action records, and lexicon_entry_draft templates, making semantic caveats and their likely lexicon repairs visible even when the translation is otherwise verified. The same draft templates are lifted to a top-level lexicon_patch_drafts field and rendered in a Lexicon Patch Drafts panel, so clients can obtain a direct candidate repair queue instead of traversing warning records. A command-line exporter and a dedicated web endpoint emit the same queue as a lexicon_patch_drafts.v1 JSON bundle for offline review or later interface download, and both can validate reviewer-supplied source states through structured draft-id/source-state pairs before any lexicon mutation is attempted; the endpoint can also return the review patch text directly as text/plain via format=patch. Ordinary analysis responses and the dedicated bundle both include a patch_text_preview field, the web page renders that text in a Lexicon Patch Text Preview panel with an Open patch text link and source-state resolution forms, and the command-line path can also write that review-only candidate patch text for the relevant StateLexiconEntry line into fresh output directories; the project-level verification script exercises that exporter path. Unresolved drafts are retained as commented pending lines rather than represented as auto-applicable source edits. Each draft has a stable draft_id and carries a state_lexicon_patch_line preview of the candidate StateLexiconEntry, with the pre-state left as a placeholder rather than silently mutating the lexicon; requires_human_choice, placeholder_fields, can_auto_apply, resolved_patch_count, and validation_errors make that guard machine-readable, conflicting repeated reviewer choices are rejected instead of silently overwritten, and patch text suppresses candidate replacement lines whenever validation errors are present. This detail is small but methodologically useful: the implementation does not merely announce that a translation failed, but records which layer failed, which successful translations remain semantically underspecified, and what kind of repair would be appropriate. For an automatic semantic translator, such stage-local diagnostics are part of the scientific artifact, because they separate weaknesses of the current parser from failures of the dependent-type replacement itself.

This stage-local diagnostic policy also applies to lexical declaration conflicts introduced by coordination. The web/API regression for John ate bread and drank bread reports failure_stage = type_check, displays the Food versus Drinkable conflict in the Type Check panel, and marks Coq/Rocq validation as skipped. This is a small but important user-interface consequence of the theory: when dependent typing detects an incompatible lexical assignment, the system should explain the typing failure rather than present it as an opaque proof-assistant compilation error.

The same interface now exposes construction_summary for matched construction rules. This is a short sentence-local explanation of the typed structure that has been recognized, displayed in the Construction Rule panel and returned by the API. For example, a transitive VP-coordination result can say that the same subject john coordinates eat(bread : Food) and drink(water : Drinkable). This does not replace the AST; it gives a human reader a quick audit hook before opening the full structured term or generated Coq.

The implementation documentation now mirrors these two coordination AST forms explicitly. The AST reference includes predicate_coordination and transitive_predicate_coordination examples, their rendered formulas, and the shallow invariants checked for predicate types, object types, and temporal scoping. This keeps the scientific exposition, implementation, web interface, and test oracle aligned as new construction-specific replacements are added.

## 12. Discussion

The framework does not claim that natural language never refers to events. Rather, it denies that every predicate must introduce a hidden event argument. Event-denoting nominals, explicit event anaphora, counting constructions, and discourse reference may still introduce episode or situation objects. The difference is architectural: event-like objects are licensed by specific constructions, not by the lexical semantics of every verb.

This modular view also clarifies disagreements about event ontology. Some empirical effects attributed to events are actually effects of modifier polyadicity, typed role structure, existential omission, temporal anchoring, aspectual process structure, or causal transition. Once these are separated, the residual need for event objects becomes narrower and more empirically testable.

## 13. Conclusion

A comprehensive replacement for event semantics must do more than solve variable polyadicity. It must also account for argument omission, thematic roles, time, aspect, event quantity, causation, and resultatives. This article has proposed a dependent-type architecture that distributes these functions across typed constructions: natural-number-indexed verb families, dependent role records, sigma and option types, temporal and aspectual operators, state-transition types, and selectively introduced episode witnesses. The resulting semantics preserves the main explanatory benefits of event semantics while avoiding a universal hidden event argument. It is also well suited to automation because each representational function is associated with a distinct typed constructor and a corresponding translation rule. The prototype strengthens this claim by showing that the target representation can be emitted as a structured AST, checked for basic type well-formedness, exported as Lean- and Coq-style formalization scaffolds, and compiled as a Coq scaffold when a local Coq/Rocq toolchain is present.
